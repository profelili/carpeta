📁 Carpeta Didáctica

Guía paso a paso para subir tu proyecto a GitHub

1

📥Descargar el proyecto

Primero necesitás descargar todos los archivos del proyecto a tu computadora.

En esta misma plataforma donde estamos trabajando ahora, buscá un botón que diga "Descargar", "Export" o "Download". Esto te va a dar un archivo ZIP con todo el proyecto.

¿Qué vas a descargar? Un archivo ZIP que contiene:

  • index.html - La página principal
  • package.json - Configuración del proyecto
  • README.md - Instrucciones
  • vite.config.js - Configuración de Vite
  • tsconfig.json - Configuración de TypeScript
  • Carpeta src/ con todo el código fuente
  • Carpeta .github/ con la configuración de publicación
2

🗂️Descomprimir el archivo

El archivo que descargaste está comprimido (es un ZIP). Necesitás descomprimirlo:

En Windows: Hacé clic derecho sobre el archivo ZIP → "Extraer aquí" o "Extract here"

En Mac: Hacé doble clic sobre el archivo ZIP y se descomprimirá automáticamente

Vas a obtener una carpeta con todos los archivos del proyecto. Dejá esta carpeta abierta, la vas a necesitar en el paso 4.
3

🌐Ir a tu repositorio en GitHub

Abrí el navegador y andá a tu repositorio:

Ir a mi repositorio en GitHub

Vas a ver la página de tu repositorio con los archivos viejos.

4

🗑️Borrar los archivos viejos

Antes de subir los archivos nuevos, hay que borrar los viejos para que no haya conflictos.

Hacé clic en cada uno de estos archivos para borrarlos:

  • index.tar - Este archivo comprimido ya no sirve
  • static.yml (si existe en la carpeta .github/workflows)

Para borrar cada archivo:

  1. Hacé clic en el nombre del archivo
  2. Arriba a la derecha, hacé clic en el ícono de lápiz (Edit this file)
  3. Arriba, hacé clic en el ícono de tacho de basura (Delete this file)
  4. Abajo, escribí un mensaje como "Borrar archivo viejo"
  5. Hacé clic en el botón verde "Commit changes"
No borres el README.md - ese archivo está bien y lo vamos a mantener.
5

📤Subir los archivos nuevos

Ahora sí, vamos a subir todos los archivos del proyecto nuevo.

En la página principal de tu repositorio:

  1. Hacé clic en el botón "Add file" (arriba a la derecha, al lado de "Go to file")
  2. Seleccioná "Upload files"
  3. Vas a ver un área que dice "Drag files here to add them to your repository"
  4. Abrí la carpeta que descomprimiste en el paso 2
  5. Arrastrá TODOS los archivos y carpetas desde tu computadora al área de GitHub
Es muy importante que subas TODO, incluyendo:
  • La carpeta src/ completa
  • La carpeta .github/ completa (¡no la olvides!)
  • Todos los archivos sueltos: index.html, package.json, README.md, etc.

Después de arrastrar todo, vas a ver una lista de archivos. Abajo:

  1. En "Commit message" escribí: "Subir proyecto completo"
  2. Hacé clic en el botón verde "Commit changes"
GitHub va a tardar unos segundos en subir todo. Es normal que veas una barra de progreso.
6

⚙️Activar GitHub Pages

Ahora necesitamos decirle a GitHub que publique tu sitio web.

  1. En la página de tu repositorio, hacé clic en la pestaña "Settings" (arriba, al lado de "Insights")
  2. En el menú de la izquierda, bajá hasta encontrar "Pages" y hacé clic
  3. En la sección "Build and deployment", vas a ver un menú desplegable que dice "Source"
  4. Cambiá el Source de "Deploy from a branch" a "GitHub Actions"
¡Listo! Con esto GitHub ya sabe que tiene que usar el archivo de configuración que subimos para publicar tu sitio.
7

⏳Esperar a que se publique

Ahora GitHub necesita compilar y publicar tu sitio. Esto tarda entre 1 y 3 minutos.

Para ver el progreso:

  1. En la página de tu repositorio, hacé clic en la pestaña "Actions" (arriba)
  2. Vas a ver una lista de "workflows" ejecutándose
  3. Buscá el que dice "Publicar en GitHub Pages"
  4. Esperá a que aparezca un tilde verde ✅ al lado
Si ves una cruz roja ❌, algo salió mal. Volvé al paso 5 y verificá que subiste TODOS los archivos, especialmente la carpeta .github/.
8

🎉¡Tu sitio está publicado!

Cuando el workflow tenga el tilde verde, tu sitio ya está en línea.

Guardá este enlace - es la dirección de tu Carpeta Didáctica en internet. Podés abrirla desde cualquier computadora, tablet o celular.

✅ Checklist final

  • Descargaste el proyecto desde esta plataforma
  • Descomprimiste el archivo ZIP
  • Borraste los archivos viejos del repositorio (index.tar, static.yml)
  • Subiste TODOS los archivos nuevos (incluyendo las carpetas src/ y .github/)
  • Activaste GitHub Pages con source "GitHub Actions"
  • Esperaste a que el workflow termine con tilde verde
  • Verificaste que tu sitio funciona en https://profelili.github.io/carpetadidactica

🎊 ¡Felicitaciones!

Tu Carpeta Didáctica ya está publicada en internet y lista para usar.

Recordá: Cada vez que hagas cambios en el proyecto, necesitás subirlos nuevamente a GitHub siguiendo los pasos 4 y 5.

Si tenés algún problema, revisá cada paso con calma. El error más común es olvidar subir la carpeta .github/ o no activar GitHub Pages.
